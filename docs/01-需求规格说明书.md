## 1. 产品概述

### 1.1 问题背景

求职者在不同招聘网站/企业官网投递时，需要反复填写高度相似的简历表单。这些表单形态各异：字段命名不同、控件实现不同（原生控件与自定义组件混杂）、常见复杂控件包括日历式日期选择器、日期区间（实习/项目起止时间）、级联选择（省市区、学校专业）、搜索式下拉、文件上传、多步分页表单等。传统按站点写死脚本的自动化工具维护成本高、无法泛化。

### 1.2 产品目标

做一款**普通求职者可直接安装使用的桌面软件**：用户一次性录入个人信息，之后面对任意简历表单页面，由 LLM 驱动的智能体自动完成填写，用户只负责最终审核与提交。

### 1.3 用户画像

| 角色 | 描述 | 核心诉求 |
| --- | --- | --- |
| 求职者（主要用户） | 校招/社招求职者，无编程背景 | 装完就能用；填得准；自己能审核 |
| 高级用户 | 有一定技术背景，自建模型端点 | 可配置模型、参数、并发；可看日志回放 |
| 开发者 | 二次开发或贡献代码 | Agent Core 可独立引用；文档与接口清晰 |

### 1.4 范围

**范围内**：浏览器中打开的任意简历/求职表单页面的自动填写；简历文件解析；填写过程监控与审计；模型端点管理。

**范围外（当前版本）**：职位搜索与推荐、自动批量海投、简历内容优化建议、面试辅助、破解验证码/风控、桌面原生应用（非浏览器）表单填写（架构预留扩展点，见 NFR-6）。

## 2. 功能需求（FR）

优先级定义：P0 = MVP 必须；P1 = 正式版必须；P2 = 增强。

### 2.1 档案中心（Profile）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-P1 | 支持上传简历 PDF/Word，由 LLM 解析为结构化档案，解析结果以表单呈现供用户校对修改 | P0 |
| FR-P2 | 支持手动创建/编辑结构化档案（核心信息）：基本信息、教育经历、实习/工作经历、项目经历、技能证书、求职意向、自我评价、附件 | P0 |
| FR-P3 | 档案字段完整度检查与提示（缺失字段在填表时可能被跳过）；按目标场景（校招/社招/公务员类官网）给出建议补全清单 | P1 |
| FR-P4 | 支持多套档案（如中文/英文简历、不同求职方向），任务发起时选择 | P1 |
| FR-P5 | 支持自定义问答知识库：用户预存开放性问题的答案（如"为什么选择我们公司"），填表时优先取用 | P1 |
| FR-P6 | 档案数据仅存本机，可一键导出/导入（JSON） | P1 |
| FR-P7 | **扩展信息体系**（很多官网会问但简历上通常没有）：性格特点、兴趣爱好、特长、MBTI/职业测评结果、语言能力（语种+等级+分数，如 CET-6/雅思）、获奖荣誉、学生干部/社团经历、家庭成员、紧急联系人、婚姻状况、身高体重、健康状况、政治面貌与入党时间、生源地/户口所在地、推荐人（Reference）、作品集/主页链接（GitHub/个人网站）、期望到岗时间、是否接受出差/外派 | P0（分批实现，见 03 §1） |
| FR-P8 | **按需注入原则**：扩展信息不随档案整体注入提示词；只有当页面表单实际出现对应字段时才检索取用（隐私最小化 + 控制 token）。表单问到、档案又没有的扩展字段，记入"待确认"清单并在报告中提示用户补充档案 | P0 |
| FR-P9 | 扩展信息的简历自动抽取：解析简历时能顺带抽出获奖、语言、社团等信息填入扩展档案；性格/爱好等主观信息支持引导式问卷录入（可选填） | P1 |
| FR-P10 | 多附件管理：多个简历版本（中/英文、不同岗位定向）、证件照（自动检查常见规格：一寸/二寸/像素/大小上限）、成绩单、证书扫描件、作品集文件；每个附件带用途标签供填表时匹配 | P0（规格检查 P1） |

### 2.2 模型配置中心（Model Hub）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-M1 | 用户可在软件设置页添加/编辑/删除模型端点：名称、base_url、api_key、模型名、temperature、max_tokens、超时、并发上限、extra_body（如 `chat_template_kwargs`） | P0 |
| FR-M2 | 一键连通性测试：自动请求 `/v1/models` 与最小对话验证；自动探测是否支持图像输入（发送 1px 测试图）并标记"视觉能力" | P0 |
| FR-M3 | 模型角色路由：Planner / Actor / Validator / 简历解析 / 文案生成 五类角色可分别绑定不同模型，默认全部使用同一默认模型 | P1 |
| FR-M4 | api_key 使用系统级加密存储（Windows DPAPI），界面不明文回显 | P0 |
| FR-M5 | 模型调用统计：token 用量、平均时延、失败率，按任务与按模型聚合展示 | P2 |

### 2.3 自动填写智能体（Agent）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-A1 | 输入任意简历表单 URL，智能体在受控浏览器中自动感知并填写表单 | P0 |
| FR-A2 | 任务拆分：Planner 将整页/多步表单拆分为区块级子任务（基本信息、教育经历、工作经历……）并生成字段 checklist | P0 |
| FR-A3 | 支持控件类型：文本框、文本域、原生下拉、自定义下拉（含搜索式）、单选/复选、日历式日期选择器、日期区间、级联选择、文件上传、富文本编辑器 | P0（富文本 P1） |
| FR-A4 | 日期能力：支持"至今"、年月/年月日多种粒度、日历面板逐级导航（年→月→日）、按占位符格式直接键入 | P0 |
| FR-A5 | 每次填写后回读校验（Validator），不一致自动重试或换策略，最多 3 次后记入失败清单 | P0 |
| FR-A6 | 多步/分页表单：识别"下一步/保存"推进，跨页维护全局 checklist | P0 |
| FR-A7 | 动态条目：识别"添加一段经历"类按钮，按档案中经历条数循环添加 | P1 |
| FR-A8 | 开放性问题：LLM 基于档案与问答知识库生成回答；无法推断的字段不乱填，记入"待确认"清单 | P0 |
| FR-A9 | iframe 内表单、懒加载长页面（滚动分段感知）支持 | P1 |
| FR-A10 | 默认不自动提交；填写完成暂停，生成填写报告（成功/失败/跳过/待确认），用户审核后手动提交 | P0 |
| FR-A11 | 敏感动作门禁：提交、删除、支付类按钮默认需人工确认 | P0 |
| FR-A12 | 登录墙/验证码：自动暂停并通知用户在受控浏览器中手动处理，处理完成后一键继续 | P0 |
| FR-A13 | **简历文件自动上传**：自动定位上传入口（含隐藏 input、拖拽区、点击弹出文件选择器三种形态），按站点要求匹配附件（格式/大小限制、中英文版本），上传后校验成功状态（进度条/文件名回显） | P0 |
| FR-A14 | **"传简历自动解析"主流程适配**：大量官网/ATS 要求先上传简历、由站点解析回填表单，智能体在上传后进入"核对修正"模式——逐字段比对站点解析结果与本地档案，纠错、补漏，而不是从零填写 | P0 |
| FR-A15 | 站点场景识别与策略：自动识别登录/注册页、隐私协议弹窗、职位列表页（需先进入申请入口）、草稿保存机制、会话超时、重复投递提示等场景并执行对应策略（详见 §6 场景库） | P0（场景分批覆盖） |
| FR-A16 | 证件照上传：匹配站点像素/大小要求，超限时本地自动压缩/裁剪（等比），无法满足时提示用户 | P1 |
| FR-A17 | 表单语言自适应：识别中文/英文表单，自动选用对应语言档案内容（结合 FR-P4 多套档案） | P1 |

## 3. 非功能需求（NFR）

| 编号 | 需求 |
| --- | --- |
| NFR-1 | **泛化性**：验收基准表单集（见 §4）覆盖率 ≥ 90% 字段正确填写；不允许针对基准表单写死选择器 |
| NFR-2 | **模型兼容**：仅依赖 OpenAI 兼容 Chat Completions 接口；视觉能力可选降级（纯 DOM 模式），30B 级本地模型可用 |
| NFR-3 | **性能**：单页 30 字段表单填写 ≤ 5 分钟（取决于模型时延）；感知层单次 DOM 提取 ≤ 2s |
| NFR-4 | **隐私**：档案、密钥、历史全部本机存储；除用户配置的模型端点外不向任何第三方发送数据 |
| NFR-5 | **可靠性**：智能体循环有最大步数与最大 token 预算护栏；异常不崩溃主程序，任务失败可重试 |
| NFR-6 | **可扩展**：感知/执行层抽象为 Driver 接口，浏览器（Playwright）为默认实现，预留纯视觉桌面 Driver（截图+坐标）扩展点 |
| NFR-7 | **可观测**：结构化日志（JSON），分级（DEBUG/INFO/WARN/ERROR），按任务归档 |

## 4. 验收标准

1. **基准表单集**：本仓库 `tests/demo_forms/` 内置 5 个模拟简历页（见 §6.3），覆盖 FR-A3 全部控件类型与主要场景，端到端测试字段正确率 ≥ 90%，关键字段（姓名/电话/邮箱/教育经历）100%。
2. **真实站点抽测**：至少 3 个真实招聘表单（国内官网/ATS 至少 1 个、海外 ATS 托管表单至少 1 个）人工验收通过。
3. **软件交付**：干净的 Windows 11 虚拟机中，安装包安装后按首次引导流程 10 分钟内完成第一次自动填写。
4. **安全验收**：填写完成后未发生任何自动提交；api_key 在磁盘上不可明文读取；扩展敏感字段（家庭成员/身份证号等）未在无关任务的提示词中出现（抽查审计日志）。

## 6. 站点复杂情况场景库

真实招聘站点远不止"一张表单"。本节枚举已知场景与智能体应对策略，是 Planner 场景识别（FR-A15）的需求基线；场景库随实测持续扩充（新增场景走文档评审）。

### 6.1 流程形态场景

| 场景 | 典型表现 | 应对策略 | 优先级 |
| --- | --- | --- | --- |
| 登录/注册墙 | 进入申请页前要求登录，常见手机验证码、微信扫码、邮箱注册 | 识别登录页特征 → 暂停转人工（FR-A12），登录后自动继续；persistent context 保留会话，同站二次投递免登录 | P0 |
| 隐私协议/Cookie 弹窗 | 首屏遮罩弹窗，需勾选同意才能继续 | 识别弹窗类型：Cookie/隐私协议自动点击同意并留审计记录；涉及授权第三方的协议暂停请用户确认 | P0 |
| 职位列表页入口 | 用户给的 URL 是职位列表/职位详情页，不是表单页 | Planner 识别页面类型，定位"申请/立即投递"按钮进入表单；找不到入口时请用户点选 | P1 |
| 简历优先流程（FR-A14） | 先传简历 → 站点自动解析回填 → 用户核对 | 上传附件 → 等待解析完成 → 进入核对修正模式（逐字段比对纠错补漏） | P0 |
| 多步向导表单 | 步骤条（基本信息→教育→经历→附件→预览），步间强制校验 | 每步填完 → 处理校验报错 → 推进；预览页停下交用户审核 | P0 |
| 单页超长表单 | 一页 50+ 字段，分区块折叠面板 | 滚动分段感知；折叠面板先展开再填 | P0 |
| 草稿保存机制 | 站点提供"保存草稿"，或切步自动保存 | 每完成一个区块顺手点保存（识别为非敏感按钮）；崩溃恢复后从草稿继续 | P1 |
| 会话超时 | 长时间填写后 session 失效，跳回登录页 | 检测意外跳转 → 暂停转人工重新登录 → 依赖草稿/checklist 恢复进度 | P1 |
| 重复投递检测 | 站点提示"您已投递过该职位/一个岗位只能投一次" | 识别提示 → 终止任务并在报告中明示，绝不尝试绕过 | P0 |
| 邮箱/短信验证环节 | 表单中途要求填验证码 | 暂停转人工 | P0 |
| 完善度门槛 | 站点要求"简历完整度 ≥ 80% 才能投递" | 完成度提示解析 → 未达标字段与档案比对 → 补填或列入待确认 | P1 |

### 6.2 平台类型画像

覆盖策略以泛化能力为主，平台画像只用于测试选型与场景权重排序，**不允许按平台写死流程**（AIHawk 教训，见 04 §2.3）。

| 平台类型 | 代表 | 特点 |
| --- | --- | --- |
| 国内 ATS 托管 | 北森（beisen）、Moka、大易、智联卓聘托管页 | 中文字段体系（政治面貌/生源地/四六级）、多步向导、简历解析回填普遍、级联选择多 |
