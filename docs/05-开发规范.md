# AutoOffer 开发规范与工程标准

| 项目 | 内容 |
| --- | --- |
| 文档版本 | v0.2 |
| 适用范围 | 本仓库全部代码（含多子智能体并行开发产出），合入前必须符合本规范 |

## 1. 代码规范

### 1.1 Python（core / server / app / cli）

- Python 3.11+，全量类型注解；公共接口禁止 `Any`（有充分理由需注释说明）。
- 格式化与静态检查：`ruff format` + `ruff check`（规则集：`E,F,W,I,N,UP,B,ASYNC,S(bandit)`），`mypy --strict`（core 包强制，server 渐进）。
- 数据结构一律 Pydantic v2 模型或 `dataclass`，禁止裸 dict 在模块间传递。
- 异步优先：Agent Core 与 server 全异步（`async/await`），禁止在事件循环中调用阻塞 IO（文件/加密等用 `asyncio.to_thread`）。
- 异常：自定义异常层次 `AutoOfferError` → `PerceptionError / ActionError / LLMError / ProfileError`；捕获必须具体化，禁止裸 `except:`。
- 日志：`structlog` JSON 输出；禁止 `print`；日志中禁止出现 api_key、身份证号、手机号明文（统一走脱敏工具函数）。
- 提示词：只放 `agents/prompts/` 下的模板文件，禁止在代码中拼接大段提示词字符串。

### 1.2 TypeScript（frontend）

- TS strict 模式；ESLint（typescript-eslint recommended）+ Prettier。
- API 类型从后端 OpenAPI 生成（`openapi-typescript`），禁止手写重复类型。
- 状态管理用 Zustand，服务端状态用 TanStack Query；组件文件 ≤ 300 行，超出拆分。

### 1.3 通用

- 命名与注释：代码标识符英文，注释与文档中文；注释只解释"为什么"，不复述代码。
- 禁止提交：密钥、真实个人信息（测试档案一律用虚构数据）、`node_modules`、构建产物。

## 2. Git 工作流

- **分支模型**：主干开发。`main` 受保护，功能分支 `feat/<workstream>-<短描述>`、修复分支 `fix/<短描述>`，经 PR 合入，squash merge。
- **提交信息**：Conventional Commits——`feat(core): 支持日历面板年月导航`、`fix(server): 任务取消未关闭浏览器上下文`。scope 取 `core/server/frontend/app/cli/docs/build`。
- **PR 要求**：关联需求编号（FR-xx）；描述含变更摘要与测试方式；CI 全绿；至少一次代码评审（多子智能体并行开发时由集成者角色评审，见 06 号文档）。
- 接口契约（`core` 的公共模型与 server 的 API schema）变更必须同步更新 `docs/03-详细设计.md` 并在 PR 中显式标注 **BREAKING**。

## 3. 测试策略（测试金字塔）

| 层级 | 范围 | 工具 | 门槛 |
| --- | --- | --- | --- |
| 单元测试 | label 归因、选项语义匹配、日期解析/格式化、档案 schema、动作 schema 校验、脱敏工具 | pytest + pytest-asyncio | core 行覆盖率 ≥ 80% |
| 集成测试 | 感知模块对本地 HTML 夹具的提取正确性；控件处理器对每类控件夹具的填写；LLM 客户端用 **mock 端点**（录制回放真实响应） | pytest + Playwright（本地静态页） | 每个 WidgetHandler 至少 3 个夹具 |
| 端到端 | 基准表单集 `tests/demo_forms/` 五个模拟简历页全流程（含简历优先流程与中文官网风格页，见 01 §6.3；需真实模型端点，CI 中标记 `@pytest.mark.llm` 可跳过） | pytest + 真实端点 | 字段正确率 ≥ 90%（验收 §4） |
| 前端 | 组件测试 + API mock | Vitest + MSW | 关键页面冒烟 |

- LLM 相关测试原则：**决策逻辑与模型解耦**——多智能体循环用假 LLM（固定脚本响应）测状态机；真实模型只在 e2e 层出现。
- 基准表单集是验收资产，修改需评审；智能体代码禁止 import 或读取 demo_forms 的实现细节（防泛化作弊，NFR-1）。

## 4. CI/CD（GitHub Actions）

| 工作流 | 触发 | 内容 |
| --- | --- | --- |
| `ci.yml` | PR / push main | ruff + mypy + pytest（unit+integration，无真实 LLM）+ 前端 lint/test/build，全矩阵 Windows + Ubuntu |
| `e2e.yml` | 手动 / nightly | 基准表单集 e2e（需自托管 runner 或密钥注入模型端点） |
| `release.yml` | tag `v*` | 版本号注入 → 打包安装程序（Windows runner）→ 产出 `AutoOffer-Setup.exe` + SHA256 → GitHub Release 草稿 |

- pre-commit 钩子：ruff、mypy（改动文件）、密钥扫描（gitleaks）、禁止大文件。
- 版本策略：SemVer；`CHANGELOG.md` 由 Conventional Commits 生成（git-cliff）。

## 5. 安全与隐私规范

1. api_key：只经 `keystore` 服务读写（Windows DPAPI），内存中用 `SecretStr`，日志/API 响应/前端一律脱敏（`sk-***12ab`）。
2. 个人档案：本机存储；发给模型端点的内容仅限用户配置的端点；身份证号等强敏感字段默认不注入提示词，命中相关表单字段时在界面单独请求授权（详见 03 §1.1）。
3. 本地服务：仅绑定 127.0.0.1；启动时生成一次性 token，前端请求携带（防本机其它进程调用）。
4. 审计数据（截图含个人信息）：保存在本机 `runs/`，提供一键清理；不上传。
5. 依赖安全：CI 跑 `pip-audit` 与 `npm audit`（high 以上阻断）。
6. 行为红线：不实现验证码绕过/风控对抗；默认不自动提交；软件内置免责声明。

## 6. 可观测性规范

- 结构化日志字段约定：`task_id / agent_role / step_seq / action_type / element_label / duration_ms / model / tokens`。
- 每个任务一个日志文件 `logs/tasks/{task_id}.jsonl`，与审计事件表互补（日志给开发者，事件表给回放 UI）。
- LLM 调用全量记录 usage 入 `llm_usage` 表（FR-M5 数据源）。

## 7. 文档规范

- `docs/` 编号文档为权威设计文档，代码与文档冲突时以文档评审结论为准并更新文档。
- 每个顶层包配 `README.md`（职责、公共接口、本包如何单独测试）。
- API 文档由 FastAPI OpenAPI 自动生成，不手写。
- 架构决策：重大选型变更追加 ADR 记录到 `docs/adr/NNNN-标题.md`（背景/决策/后果，一页以内）。
